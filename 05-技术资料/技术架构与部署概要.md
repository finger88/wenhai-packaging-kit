# 问海 · 技术架构与部署概要（脱敏版）

> 供技术评审应答与材料②技术章节参考。不含任何密钥与客户环境信息。

## 1. 总体架构

```
浏览器 (http://<服务器>/)
   │
   ├─ 应用服务容器（网页 + API 一体，Python FastAPI）
   │     ├─ AI 大模型 ──▶ OpenAI 兼容接口（云端 API / 内网本地大模型，可插拔切换）
   │     ├─ 语义向量 ──▶ 本地向量化服务（bge-m3，1024 维）
   │     ├─ OCR ──────▶ PaddleOCR（容器内本地识别，支持纯 CPU）
   │     └─▶ PostgreSQL 16 + PostGIS（空间）+ pgvector（向量）+ OnlyOffice 文档服务容器
   │
   └─ 报告引擎：python-docx + lxml，Word 内容控件（SDT）占位符，
      支持字段替换 / 表格行克隆 / 章节循环 / 自动插图四类占位符
```

## 2. 关键选型与理由

| 选型 | 业务理由 |
|------|---------|
| RAG 问答 + 引用角标 | 监管答复必须可溯源，回答只基于平台内原文，杜绝大模型编造 |
| pgvector 单库混管空间与向量 | 一套数据库同时支撑地图 GIS 与语义检索，运维简单，适合地市客户 |
| OnlyOffice 集成 | 报告模板所见即所得在线编辑，业务人员零学习成本 |
| SDT 内容控件报告引擎 | 比文本占位符替换强在表格行克隆与整段循环；与海域业务零耦合，可提炼为通用报告工具 |
| 模型 OpenAI 兼容接口 | 云端与内网本地模型一键切换，不锁定厂商 |
| 全组件可本地化 | 大模型、向量、OCR 均可内网部署，监管数据不出内网 |

## 3. 部署形态（三种环境同一套镜像）

| 环境 | 构成 | 用途 |
|------|------|------|
| 公网演示环境 | 云服务器（4 核 8G 起）Docker 部署 + 云端大模型 API + 虚构演示数据 | 参赛评审，国内公网可访问 |
| 客户生产环境 | 客户内网 Linux 服务器 + 本地大模型/向量服务，离线镜像包交付 | 数据不出内网的生产运行 |
| 开发环境 | 本机 Docker Desktop | 持续迭代与回归验证 |

- 交付物：离线镜像包（约 4GB）+ 部署文档 + 演示数据种子（可选）
- 自行部署约 1~2 小时（docker load → 改一处配置 → docker compose up）
- 运维：一键启停脚本、健康检查接口、双卷数据备份、演示数据一键重置

## 4. 工程质量记录（真实问题修复案例）

研发期在真实环境中发现并通过「补丁挂载制」（不改镜像，配置化覆盖）修复的问题：

| 问题 | 根因 | 修复 |
|------|------|------|
| 问答/合同识别报 LLM 400 | 部分云端模型强制 temperature=1，原代码写死低温度 | 温度改为可配置项（.env 一行切换，对不限温度的模型零影响） |
| 报告模板在线编辑无法保存 | OnlyOffice 保存回调地址用了它自身视角的主机名，应用容器连不通 | 回调地址改写为内部可达地址 |
| 地图底图空白 | 原瓦片源国内不可达 | 切换瓦片源；内网完全离线时属环境属性，如实告知 |

这套机制的价值：问题定位→修复→随交付包走全流程有记录，交付包不携带开发环境配置与密钥。
