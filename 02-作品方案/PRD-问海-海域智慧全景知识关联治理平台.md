## 1. 产品概述

**问海**（正式名：海域智慧全景知识关联治理平台）是一个面向海域使用监管业务的 AI 智能体应用：把分散在合同、台账、照片、图件中的监管资料汇聚为一个可对话、可检索、可出报告的知识库，让监管人员**用一句自然语言，查遍全部项目资料；用一次点击，生成规范报告**。

- **服务对象**：自然资源主管部门与技术服务单位中的海域使用监管人员、项目负责人、审核人员
- **产品形态**：B/S 网页应用（浏览器直达，无需安装），Docker 一体化交付，支持**有网、无网（内网离线）两种部署形态**
- **AI 能力**：大语言模型问答与信息抽取、向量检索（语义搜索）、OCR 文字识别、Word 报告自动生成
- **当前状态**：研发完成，全功能在本机环境实测通过，已具备客户生产环境交付条件

### 对接集团产业方向

本产品紧扣集团**自然资源资产经营保护**与**资源空间安全利用保障**两大产业方向，解决海域使用监管（用海审批后的持续监管）业务中资料多、检索难、报告累的核心痛点，方法可复制到地灾防治、地质勘查、生态修复等其他自然资源业务场景。

## 2. 业务背景与痛点

### 2.1 业务场景

海域使用监管的基本单元是「**监管项目 → 宗海 → 季度核查**」：一个区县一份监管合同对应多个用海项目（宗海），每宗海按季度开展现场核查，产出核查记录、现场照片、权属图件；监管周期结束时，需要汇总全部资料出具**核查报告**。

一个中等规模监管合同，一年累计产生的资料包括：合同扫描件、数百份核查记录与照片、多期用海矢量图件、若干份动辄数十页的核查报告。

### 2.2 四大痛点

| # | 痛点 | 现状做法 | 后果 |
|---|------|---------|------|
| 1 | **资料散、查得慢** | 资料分散在各人电脑里，靠文件夹和文件名记忆 | 找一份历史核查记录要翻几个人、几十个文件夹 |
| 2 | **看不懂、用不上** | 合同、报告多为扫描件和长文档，信息无法直接利用 | 新接手人员要花数周通读资料才能上手 |
| 3 | **报告累、易出错** | 核查报告靠人工从各处摘数、贴照片、排版 | 一期报告多人天；数据口径不一、漏图漏项时有发生 |
| 4 | **经验难传承** | 「哪个词该查哪类资料」「报告怎么写」都在老同志脑中 | 人员一变动，工作质量就波动 |

### 2.3 AI 带来的改变

把「人找资料」变成「资料找人」：资料一次性规范汇入平台，之后**提问即得答案（附原文出处）**、**生成报告即组装数据**、**扫描件即变可用数据**。原来分散在规范和个人经验中的能力，沉淀为系统中的标准化流程。

## 3. 产品目标与价值

| 目标 | 可衡量效果 |
|------|-----------|
| 检索提效 | 历史资料查询从「几十分钟到几天」缩短到「**秒级问答**」，且答案附原文引用、可溯源 |
| 报告提效 | 标准核查报告的资料组装与排版从「多人天」压缩到「**分钟级生成 + 人工定稿**」 |
| 降低差错 | 数据从平台统一调取、图片按模板自动落位，杜绝漏贴错贴；生成前**数据预检**自动查缺补漏 |
| 统一标准 | 报告格式、数据口径由模板统一约束，全部门产出一个标准 |
| 传承经验 | 新人直接向平台提问即可了解项目全貌，老同志的经验以「规范资料库」形式留存 |
| 数据安全 | 支持**全内网离线部署**（大模型、向量服务全部本地化），敏感监管数据不出内网 |

### 5.2 四大 AI 能力（差异化亮点）

**① 全景地图智能检索** —— 一张地图看全辖区
项目以色点与用海矢量色块呈现在地图上，颜色代表状态（进行中/已完成/已归档）；点空白处自动找出周边约 50 公里内的项目；点击项目即聚合展示基本信息、核查记录（含现场照片）、关联文档，一键打包下载全部资料。

**② AI 智能问答（检索增强生成）** —— 像问一个老监管
用自然语言提问（「XX 区有哪些用海项目？」「某项目的用海期限到什么时候？」），平台先从全部资料中**语义检索**最相关的原文片段，再由大模型归纳作答——回答只基于平台内真实资料，并**附 [1][2] 角标引用**，点开即见原文与数据期次，可多轮追问、可限定在单个项目内提问；回答提到具体项目时，地图自动定位联动。语义检索由本地向量化服务（bge-m3）驱动，即使关键词不完全匹配也能「按意思」找到资料。

**③ 合同 AI 识别** —— 扫描件变台账
上传监管合同扫描件（PDF），OCR 识别 + 大模型抽取，自动读出委托单位（甲方）、承担单位（乙方）等关键信息供人工核对确认，作为报告的数据来源，免去人工摘录。

**④ 报告智能生成** —— 模板 + 数据 → 成稿 Word
报告模板以 Word 内容控件定义字段占位符（正文字段、表格行、章节循环、图片位），在线编辑模板实时保存；生成时平台自动组装项目数据、核查记录、团队名单与区县图集照片（同一位多张自动排成图 a/b/c），**生成前数据预检**逐项列出缺项并支持一键跳转补齐，缺项可先出草稿、补全后覆盖重生成。图片自动按 A4 满版宽落位，页眉页脚、目录结构完整保留。

## 7. 技术架构概貌

> 本节面向技术评审，业务阅读可跳过。

```
浏览器 (http://<服务器IP>/)
   │
   ├─ 应用服务容器（网页 + API 一体，Python FastAPI）
   │     ├─ AI 大模型 ──▶ OpenAI 兼容接口（云端 Kimi / 内网 qwen3.6-35b-a3b，可插拔）
   │     ├─ 语义向量 ──▶ bge-m3 本地向量化服务（1024 维）
   │     ├─ OCR ──────▶ PaddleOCR（容器内本地识别，支持纯 CPU）
   │     └─▶ PostgreSQL 16 + PostGIS（空间）+ pgvector（向量）+ OnlyOffice 文档服务容器
   │
   └─ 报告引擎：python-docx + lxml，Word 内容控件（SDT）占位符，
      支持字段替换 / 表格行克隆 / 章节循环 / 自动插图四类占位符
```

关键选型的业务理由：
- **检索增强生成（RAG）+ 引用角标**：监管答复必须可溯源，杜绝大模型「编造」——回答只允许基于平台内原文；
- **pgvector 单库混管空间与向量**：一套数据库同时支撑地图 GIS 与语义检索，运维简单、适合地市客户；
- **OnlyOffice 集成**：模板所见即所得在线编辑，业务人员零学习成本；
- **SDT 内容控件报告引擎**：比「文本占位符替换」强在支持表格行克隆与整段循环，复杂报告也能模板化；该引擎与海域业务零耦合，可提炼为通用报告工具。

## 9. 推广规划（迭代升级空间）

**同类业务横向复制**：平台的数据模型（合同 → 项目 → 核查 → 报告）与 AI 链路（问答/识别/报告）是通用的，可低成本复制到——
- 海洋调查数据管理、地灾治理项目管理、矿山修复监管、耕地保护监测等自然资源条线业务；
- 任何「资料汇总 + 检索问答 + 周期性报告」场景的政府部门与企事业单位。

**产品化路线图**：

| 阶段 | 内容 |
|------|------|
| 近期（已完成） | 海域监管全链路：检索、问答、识别、报告 |
| 中期 | 报告引擎提炼为通用本地批量报告工具（模板 + Excel/JSON 数据 → 批量 Word），脱离平台复用 |
| 中期 | 无人机照片自动归属矢量分析（照片定位 + 最邻近矢量匹配），支撑空间资源监测 |
| 远期 | 规范知识库 + 报告规范性自动审查（对报告出带条款的合规清单）；海洋多要素数据分析扩展 |
