# 问海 · 演示脚本与风险规避（路演底稿）

> 主口径（辅导方案已定）：**一句话查遍全部项目资料 + 溯源可核验**。
> 演示环境：公网部署 + 虚构演示数据（澜海市临澜县/沧屿县，2 合同 / 9 项目 / 16 期核查，
> 详见 `06-演示数据/`）。录屏兜底：演示全程提前录一版。

## 主线演示脚本（约 5 分钟）

| 步骤 | 操作 | 讲解要点 |
|------|------|---------|
| ① 地图找项目 | 打开「项目检索」，悬停色块、点开 1 个项目详情 | 一张地图看全辖区：项目状态颜色、用海矢量范围、周边 50km 查找 |
| ② AI 问答 + 溯源 | 问「临澜县有哪些用海项目？」→ 点 [1] 角标看原文 → 追问「临澜湾海底原油管道工程的用海期限多久？」 | 秒级回答；**角标点开是原文**，监管答复可核验；多轮追问；地图自动定位 |
| ③ 限定项目问答 | 在管道项目详情里点对话气泡，问「最新一期核查发现了什么」 | 限定单项目检索，答出 Q2 现场记录（含一处超范围整改线索，展示业务深度） |
| ④ 合同 AI 识别 | 后台上传一份新合同扫描件 → 立即识别 → 展示草稿核对 → 确认 | 扫描件变台账：OCR + 大模型抽取甲乙方、金额、服务内容，人工审核兜底 |
| ⑤ 报告一键生成 | 报告中心 → 选区县/期次 → 生成（先展示数据预检弹窗）→ 下载 Word | 多人天 → 分钟级；预检查缺补漏杜绝漏项；图片自动落位 |
| ⑥ 收尾 | 回到地图总览 | 全内网可离线部署，数据不出内网；可复制到地灾/勘查/生态修复等条线 |

## 演示风险规避表（彩排前逐条过）

| 风险 | 规避动作 |
|------|---------|
| 统计类问答答不准（RAG 机制：只喂检索前 8 块） | **绝不问「总共有多少个项目」**；只问内容类问题；统计需求演示项目列表页 |
| 向量/大模型服务掉线 | 演示前跑一遍健康自检（平台 /api/health + 问答冒烟测试）；异常时切录屏 |
| 合同识别 OCR 慢（纯 CPU） | 选页数少的合同（演示合同仅 4 页）；可提前预跑到「识别中」再现场点确认 |
| 大模型 API 并发/额度限制 | 演示环境配足额度；控制彩排次数 |
| 浏览器缓存旧前端 | 演示机 Ctrl+F5；评委首次访问无此问题 |
| 问答答「现有资料不足」 | 属正常（资料确实没有），准备一句口径：「平台只基于已汇入的真实资料作答，这也是可溯源的体现」 |
| 网络故障 | 录屏兜底（完整主线一版 + 分步骤版） |

## 评委可能追问的应答口径（初稿）

- **数据是真的吗？**——演示环境为虚构数据（涉密合规）；生产环境对接真实监管资料，
  已在客户内网完成部署前勘察，具备交付条件。
- **和通用 AI 助手区别？**——三个差异：回答强制引用平台内原文（可点开核验）、
  与 GIS 地图联动、面向监管报告的模板化生成引擎；且可全内网离线。
- **大模型幻觉怎么办？**——RAG 检索增强 + 引用溯源 + 「资料不足」如实告知，不编造。
- **能否统计汇总？**——统计以台账列表页为准；问答定位是内容检索。（产品路线：区县清单块）
- **部署门槛？**——Docker 三容器离线包，一台 Linux 服务器 1~2 小时部署；模型可插拔。
