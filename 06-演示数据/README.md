# 06 · 虚拟演示数据

## 为什么是虚拟数据

比赛要求作品**部署在国内公网**供评委访问。真实监管资料（合同扫描件含真实单位与签章、
精确的宗海坐标与矢量、现场照片关联真实项目）不适合也不应放上公网。因此演示环境使用
一套**完全虚构**的数据，业务结构与真实完全一致。

对外口径：**演示环境为虚构数据；生产环境对接真实监管资料，已在客户内网完成部署前勘察。**

## 虚构世界观

浙江省澜海市（虚构）→ 临澜县 / 沧屿县。甲方为两县自然资源和规划局（虚构），
乙方为虚构联合体。详细设计见 [DATASET-DESIGN.md](DATASET-DESIGN.md)。

| 数据 | 规模 |
|------|------|
| 监管合同 | 2 份（图片型扫描件 PDF，4 页/份，含程序绘制印章） |
| 宗海项目 | 9 个（8 类用海方式，3 种状态） |
| 核查记录 | 16 条（2026-Q1 ×9 + 2026-Q2 ×7），每条 3~8 张现场照片 |
| 现场照片 | 复用原演示照片池 29 张（经确认不含文字性敏感信息，与虚构主体无关联） |
| 矢量 | 12 个虚构多边形（GeoJSON） |
| 报告模板 | 2 份（自既有模板复用，内容经检查无真实地名） |

## 构建方式（可复现）

数据不是手填的，而是**用平台真实业务流程导入**：生成虚构源文件（合同 PDF、
WPS 式嵌图 Excel）→ 走平台的上传/AI 识别/批量导入/矢量/图集 API → 重建问答索引。
好处：数据在系统内是"原生"的（原始字段、照片关联、引用溯源全部一致），同时验证了产品链路。

构建脚本（Python，随本目录提供）：

| 文件 | 作用 |
|------|------|
| `build/dataset.py` | 数据集单一事实源（改这里即可调整全部虚构数据） |
| `build/gen_contracts.py` | 渲染图片型合同 PDF |
| `build/gen_excel.py` | 生成 WPS DISPIMG 式嵌图核查 Excel |
| `build/build_vectors.py` | 生成虚构矢量 SQL |
| `build/import_runner.py` | 走平台 API 编排导入全流程 |
