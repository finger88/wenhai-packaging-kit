# 虚拟演示种子 · 使用说明

> 种子来源：在隔离实例（项目名 `ocean-vm`，与生产/本机原实例互不影响）中走平台真实业务流程
> 导入虚构数据后导出。数据内容见 [DATASET-DESIGN.md](DATASET-DESIGN.md)。

## 种子构成

| 文件 | 大小 | 说明 |
|------|------|------|
| `ocean_seed_virtual.sql` | ~0.8MB | 数据库全量导出（pg_dump，含问答索引块；账号新闻等见表内） |
| `uploads_virtual.tar.gz` | ~380MB | 上传文件目录（合同 PDF、核查照片、图集、报告模板、生成报告） |
| | | ⚠️ tar 包二进制**不随本仓库分发**，部署时由团队本地生成或另行传输 |

演示账号（导入后即时可用，公网环境上线**必须改密**）：

| 账号 | 角色 | 密码 |
|------|------|------|
| admin | 管理员 | 部署时初始化的密码（INIT_ADMIN_PASSWORD） |
| pm_lin / pm_ye | 项目负责人（临澜/沧屿） | 由导入时的 DEMO_ADMIN_PASS 约定 |

## 导入步骤（目标环境需已跑起平台容器）

```bash
cd <部署目录 bundle/>
docker compose down -v                # ⚠️ 清空现有数据；确认目标环境可清
docker compose up -d postgres
sleep 15
docker compose exec -T postgres psql -U ocean -d ocean < seed/ocean_seed_virtual.sql
docker compose up -d

# 导入演示文件（照片/合同/模板/图集）
mkdir -p /tmp/ocean-seed && tar -xzf seed/uploads_virtual.tar.gz -C /tmp/ocean-seed
docker compose cp /tmp/ocean-seed/uploads/. backend:/app/backend/data/uploads/
```

说明：

- 种子内问答索引向量由 **bge-m3** 计算；若目标环境向量服务同为 bge-m3（默认），
  无需重建索引；换用其他 Embedding 模型时，用 admin 登录 →「资料文件」→「重建索引」。
- 导入后用 admin 登录改掉全部演示密码；`pm_lin` / `pm_ye` 密码同样要改。
- 大模型配置取目标环境 `.env`（演示推荐云端 API；合同识别/问答依赖可用的大模型与向量服务）。

## 重新制备 / 调整数据

全部数据由 `build/` 脚本生成并可一键重放（改 `dataset.py` 即改全量数据）：

```bash
python gen_contracts.py     # 合同 PDF
python gen_excel.py         # 核查 Excel（WPS 嵌图）
python build_vectors.py     # 矢量 SQL
python import_runner.py --base http://<实例地址>   # 走平台 API 全流程导入
```

`import_runner.py` 全流程幂等（已确认的合同跳过、同项目同期次核查去重、模板/图集按名去重），
可反复重跑。制备用大模型经 OpenAI 兼容接口（任意可用模型均可，识别质量稳定）。

## 已知注意事项（制备过程实测）

- **本地 OCR 内存**：镜像内置 PaddleOCR 默认 server 级模型，纯 CPU 上子进程可能被 OOM 杀掉
  且进度字段不更新（长错误写入 varchar(200) 失败会卡住状态，属产品小 bug，建议修复）。
  vm 实例已通过补丁切换 `PP-OCRv5_mobile_det/rec` 轻量模型，识别质量满足演示。
- **平台 `city` 字段语义**：批量导入时 `city` 存的是**区县名**（"城市/区县"），
  报告的委托/承担单位按 `Project.city == region` 匹配合同——导入时勿填地级市名。
